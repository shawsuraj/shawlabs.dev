Sky Portal

Sky's engineering teams were tracked in a spreadsheet. We built a web app to replace it: find any team, see who it depends on, message them and book a meeting.

Built by a team of five · Code on GitHub

What it does

  • Dashboard. Total teams, departments, unread messages, recently visited teams and recent activity.
  • Teams. Search and filter every engineering team, then open one to see its mission, manager, members, code repositories and dependencies.
  • Organisation. An interactive network map of how teams depend on each other, filterable by department and dependency type.
  • Messages. Inbox, sent, drafts and compose, for messages between teams.
  • Schedule. A calendar, upcoming meetings and a form to book one.
  • Accounts. Register, log in, reset a password and update a profile.

My part

I led the interface design. I drew the low fidelity wireframes in Figma, then three storyboards showing complete journeys: register and log in, search for a team and open it, and message or book a meeting with that team. Then the high fidelity designs, refined with feedback from the group and our tutor.

The design rules were simple, because the users are engineers, managers and non-technical staff:

  • A fixed sidebar, with the current page highlighted.
  • Search at the top, because finding a team quickly was the main requirement.
  • Team cards, with tabs for overview, members, repositories and dependencies.
  • Blue for actions, green for active status, red for notifications, on a neutral background.

In the build, I made the dashboard, the organisation map and the shared base template that every page sits on.

The rest of the team

Vinicius designed the ERD and built the teams pages. Muhammed designed the database. Hamdan built messaging and wrote the user test plans. Shqipdon built scheduling and wrote the admin test plans. I reviewed the ERD and database against the requirements, and pointed out repeated attributes that could be simplified, and a missing audit log use case for admins.

Under the hood

Django and SQLite. The database follows the ERD: an organisation has departments, departments have teams, and users join teams through a team member table. Skills, repositories and team dependencies hang off each team, with tables for messages, meetings and an audit log of changes. A script seeds it all from the original spreadsheet. The organisation map is drawn with vis.js from a JSON endpoint.

What I would do differently

  • Understand the ERD and use cases before designing screens. Once I did, the screens got much easier.
  • Learn the tool first. I learned Figma while designing, which slowed the first weeks.
  • Leave the fine visual detail until the flows are right.
  • Set firm deadlines instead of extending them, especially for the database, which ran late.
