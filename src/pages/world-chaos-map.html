Measuring chaos without picking favourites.

World Chaos Map gives every country a score from 0 to 100, every four hours, using only what the news reports. This is how it works, what I got wrong, and what I changed.

01The question

Can the news alone tell you where things are falling apart?

In late 2025 the news felt overwhelming: conflicts, protests, disasters and cyber attacks, all scrolling past with no shape. I wanted one map that showed where pressure was building, and I wanted it honest enough that I could defend every number on it.

The hard part is not drawing the map. It is scoring 250 countries fairly from messy, uneven, multilingual news, where some countries get a hundred articles a day and some get one a week.

02The rule
The news dictates the chaos, not my opinion.No country appears in any list, cap, floor or override. Identical news about two different countries produces identical scores, and a unit test enforces it.

Every design decision after this had to pass that rule. It is also why the model is a set of rules I can explain, not a black box: when a score looks wrong, I can point to the article and the step that moved it.

03The pipeline

Every four hours, a rolling 26 hour window.

StepWhat happens
1 IngestRSS feeds read concurrently, plus USGS, GDACS, ReliefWeb, WHO and GDELT. Runs on GitHub Actions.
2 CleanNormalise, de-duplicate in memory, bulk upsert incidents and their sources to Supabase.
3 PlaceRe-attribute every story to the country it happened in, not where the attacker came from.
4 HarmScore each article for real harm: deaths, injuries, arrests, airstrikes, curfews.
5 StoriesGroup articles about the same event in the same country within 48 hours.
6 DayTurn each day's stories into one daily intensity, led by the worst events.
7 TrendCombine a 30 day level, a memory of lethal violence and a surge against the country's own baseline.
8 ScoreMap to 0 to 100, smooth the fall, band it, and serve it to the map through a CDN.

"Russian strike on Kyiv" is Ukraine. "Houthis target Riyadh airport" is Saudi Arabia. The place being hit wins.

04Reading harm

Deaths count most. Reactions are not events.

Each article gets a harm signal between 0 and 1, built from the evidence in it. Volume is not evidence: a heavily covered but calm country produces many low harm stories, which barely move the score.

Each day's stories then combine into one daily intensity. The worst event sets the day, and every extra story adds with diminishing returns:

D = 1 − exp(−S / 0.35), S = Σ Wi² · 0.5i

That one line replaced a whole list of special cases from v2.

05What v2 got wrong

Every hardcoded rule was a confession.

Version 2 worked, but only because I kept patching it. When a country looked wrong I added a rule for it. By the end, the map reflected my patches as much as the news. Version 3 rebuilt the score from scratch and deleted all of them:

  • HIGH_VOLUME_COUNTRIES, 43 hardcoded countries whose scores were discounted
  • LOW_EVENT_SOFT_CAP, which pinned about 15 countries at exactly 55
  • STABLE_COUNTRIES, a severity cap applied during ingestion
  • Spillover dampening, which cut the scores of invaded countries such as Ukraine
  • Floors, boosts and volume penalties, each added to fix one country at a time

On the same data, v2 put France at 31 and Ukraine at 75. Nobody could explain why without reading my code.

06Backtest

Deadly violence now outranks riots.

Every change is replayed on a real data export before it ships. In v3.2.0, riots without deaths were capped below lethal violence, and wars with killing reported on several days got a longer memory. Replayed on 7 October 2026:

Somalia, DR Congo and Niger still score low on this export, because it holds almost no reports of deaths for them. That is a coverage problem, not a formula problem, and it is fixed with better sources, not a manual override.

07The news supply

Accuracy first: repairing the inputs.

A model is only as good as what it reads. An audit in October 2026 found that only about 420 of 1,162 listed feeds had ever worked, official alerts had stopped arriving, and GitHub was skipping about a third of scheduled runs.

118feeds repaired
29local feeds added
487feeds removed
486feeds now, all checked

The audit runs by hand so every source change is reviewed. New feeds were added for places the map under-covered, such as Somalia, DR Congo, Sudan, the Sahel and Myanmar. robots.txt is respected everywhere, and known state propaganda outlets are dropped before processing. A watchdog inside Supabase restarts the ingest when GitHub skips a run.

08Free tier

Built to run for nothing.

Everything runs on the free tiers of GitHub Actions, Supabase and Vercel. That shaped the design: each run reads only the scoring columns of about 18,000 incidents (around 8 MB), writes in a few bulk requests instead of thousands of single rows, and keeps only aggregates from GDELT. The map is served through a CDN cache and polls every five minutes, pausing in hidden tabs.

09Limits

What the score is not.

It measures recent, observable, reported pressure. It is not a prediction or a risk forecast. Where coverage is thin, confidence is shown as low, and a score built mostly from gap filling is capped at medium confidence. The methodology, sources and changelog are public on the docs site.
